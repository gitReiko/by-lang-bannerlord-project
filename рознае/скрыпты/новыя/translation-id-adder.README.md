# Дадаваньне ID перакладу ў XML

Адкрыйце `translation-id-adder.html` у сучасным браўзэры. Усталёўваць праграмы ці падлучацца да інтэрнэту ня трэба.

1. Выберыце адзін або некалькі XML-файлаў, напрыклад тры `bellum_title_styles_*.xml`, або ўстаўце XML у тэкставае поле.
2. Увядзіце прэфікс. Па змоўчаньні ён `BC`; пусты прэфікс таксама дазволены.
3. Выберыце гатовыя правілы або адрэдагуйце табліцу.
4. Націсьніце **Дадаць ID**, паглядзіце XML і справаздачу.
5. Спампуйце асобны XML або ZIP з усімі вынікамі. Зыходныя файлы не перазапісваюцца аўтаматычна.

## Фармат з вашага прыкладу

| Элемэнт | Атрыбуты | Шаблён ID | Прыклад |
| --- | --- | --- | --- |
| `BellumFeudalTitles` | `presetName` | `{prefix}.{presetId}.{attribute}` | `BC.anglicized.presetName` |
| `TitleName` | `name` | `{prefix}.{id}.{attribute}` | `BC.duchy_ebor.name` |
| `Rank` | `titleName`, `maleRank`, `femaleRank`, `heirRank`, `femaleHeirRank`, `childRank`, `femaleChildRank`, `nobleRank`, `femaleNobleRank` | `{prefix}.{parent.culture\|parent.kingdom\|parent.rulerCulture}.{tier}.{attribute}` | `BC.Empire_w.Empire.maleRank` |

Напрыклад:

```xml
<TitleName id="duchy_ebor" name="{=BC.duchy_ebor.name}Ebor" />
```

Гэтыя правілы ўключаныя па змоўчаньні. Для `Rank` фармат — **прэфікс + культура + tier + назва атрыбута**. З прэфіксам `anglicized` элемэнт `TitleStyle culture="Empire_w"` атрымае, напрыклад, `maleRank="{=anglicized.Empire_w.Empire.maleRank}Emperor"`. Калі ў `TitleStyle` няма `culture`, бярэцца `kingdom`, а пасьля — `rulerCulture`.

Аднолькавыя культуры і `tier`, а таксама назвы `TitleName`, могуць мець розны тэкст у розных наборах Bellum. Інструмэнт паказвае такія канфлікты і не зьмяняе ID самастойна.

Для апрацоўкі трох набораў без гэтых канфліктаў ёсьць варыянт **Bellum Civile: з наборам і культурай/каралеўствам**:

```text
TitleName: {prefix}.{ancestor.presetId}.{id}.{attribute}
Rank:      {prefix}.{ancestor.presetId}.{parent.culture|parent.kingdom|parent.rulerCulture}.{tier}.{attribute}
```

Ён дае, напрыклад, `BC.anglicized.duchy_ebor.name` і `BC.anglicized.Empire_s.Empire.maleRank`. Калі ў `TitleStyle` няма `culture`, бярэцца `kingdom`, а пасьля — `rulerCulture`.

## Іншыя XML

Варыянт **Унівэрсальныя: id + назва атрыбута** апрацоўвае `name` і `text` ва ўсіх тэгах. Табліца дазваляе дадаваць любыя назвы тэгаў, атрыбуты і шаблёны. `*` у назьве элемэнта азначае ўсе тэгі; назвы адчувальныя да рэгістру. Атрыбуты пералічваюцца праз коску, кропку з коскай ці прабел. Для атрыбута выкарыстоўваецца першае адпаведнае правіла.

У шаблёне даступныя:

- `{prefix}`, `{attribute}`, `{tag}`, `{file}` — прэфікс, назва атрыбута, тэг, назва файла без пашырэньня.
- `{id}`, `{tier}`, `{key}` і любая іншая назва — значэньне атрыбута гэтага элемэнта.
- `{parent.culture}` — атрыбут бацькоўскага элемэнта.
- `{ancestor.presetId}` — атрыбут найбліжэйшага продка, у якога ёсьць непустое значэньне.
- `{parent.culture|parent.kingdom}` — першае непустое значэньне з гэтых варыянтаў.

Калі значэньня для шаблёну няма, атрыбут застаецца без новага ID і трапляе ў справаздачу. Пусты прэфікс дазволены. ID падтрымліваюць літары, лічбы, кропкі, `_`, `-` і `:`. Прабелы і дужкі ў ID не дазволеныя.

Пустыя атрыбуты прапускаюцца. Існыя маркеры `{=…}`, у тым ліку `{=!}` і `{=*}`, захоўваюцца; паўторная апрацоўка не дадае другі маркер. Камэнтары, CDATA і тэкст паміж тэгамі не апрацоўваюцца.

Каб прымяніць зьменены шаблён да ўжо спампаванага выніку, нанова апрацуйце зыходны XML без маркераў: існыя ID аўтаматычна не перафармоўваюцца.

Камэнтары, водступы, пераносы радкоў, двукосьсі, сутнасьці XML і зьменныя ў атрыбутах захоўваюцца. Вынік спампоўваецца ў UTF-8; калі зыходны XML абвяшчаў іншае кадаваньне, абвяшчэньне мяняецца на `utf-8`.

Дадаткова можна спампаваць `strings.xml` з зыходным тэкстам у фармаце Bannerlord. Гэтая кнопка даступная, калі няма памылак і канфліктаў. Аднолькавыя ID з аднолькавым тэкстам аб'ядноўваюцца. У табліцу ўваходзяць толькі атрыбуты, выбраныя правіламі; `{=!}` і `{=*}` выключаюцца. Справаздача JSON зьмяшчае ўсе канфлікты і іх крыніцы.

## Праверка

З кораня рэпазыторыя ў Windows можна запусьціць 10 праверак у фонавым Microsoft Edge:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "рознае/скрыпты/новыя/translation-id-adder.tests.ps1"
```

Тэсты выкарыстоўваюць асобны часовы профіль браўзэра і тры зыходныя Bellum XML побач з HTML. Правяраюцца патрабаваныя ID, поўнае пакрыцьцё выбраных атрыбутаў, захаваньне XML, паўторная апрацоўка, канфлікты, кадаваньні, ZIP і элемэнты інтэрфэйсу. Іншы шлях да Edge або Chrome можна перадаць праз `-BrowserPath`.
