# Падрыхтоўка радкоў для перакладу

1. Адкрыйце `translation-preparer.html` у Edge, Chrome або іншым браўзэры з выбарам тэчкі. Сервер і інтэрнэт не патрэбныя.
2. Выберыце `ModuleData` або іншую тэчку з англійскімі зыходнікамі. Выбар уключае ўсе яе падтэчкі.
3. Пакіньце `EN / eng-GB / English` для англійскага набору. Для нарыхтоўкі беларускага перакладу можна задаць `BE / bel-BY / Belarusian`: тэкст усё роўна будзе ўзяты з зыходнікаў на англійскай.
4. Націсьніце **Сабраць радкі**. Праверце памылкі і ID з розным тэкстам. У табліцы можна выбраць патрэбны варыянт кожнага такога ID.
5. Націсьніце **Спампаваць ZIP з XML**. У архіве будуць `Languages/EN/language_data.xml`, XML-файлы радкоў і `extraction-report.json`.
6. Перакладзіце атрыбуты `text`, захаваўшы ID і гульнявыя зьменныя. Пасьля перакладу скапіруйце тэчку мовы ў `ModuleData/Languages`.

Прыклад пераўтварэньня:

```xml
<!-- Зыходнік -->
<string id="str_faction_official.empire"
        text="{=taom_str_faction_official.empire}a clansman of Dunland" />

<!-- Файл для перакладу -->
<string id="taom_str_faction_official.empire" text="a clansman of Dunland" />
```

Ідэнтыфікатар бярэцца з `{=…}`, а не з атрыбута `id` зыходнага элемэнта. Выходны фармат паўтарае польскія файлы: `<base type="string">`, `<tags>`, `<strings>` і рэгістрацыя файлаў праз `<LanguageFile xml_path="…" />`.

XML, XSLT і XSL апрацоўваюцца праз XML-парсэр на ўсіх узроўнях укладзенасьці: атрыбуты, тэкст элемэнтаў, CDATA і `xsl:attribute` / `xsl:text`. Камэнтары не ўключаюцца. JSON апрацоўваецца як дрэва ўсіх тэкставых значэньняў, у тым ліку ў масівах. Гэта дазваляе сабраць таксама радкі з `factionmap/factions.json`.

Па змаўчаньні скануюцца `xml, xslt, xsl, json`. Можна дадаць іншыя пашырэньні або `*` для ўсіх тэкставых файлаў. Для іншых фарматаў пошук працуе па радках і значэньнях у двукосьсі; шматрадковыя значэньні і экранаваньне мовы праграмаваньня могуць запатрабаваць ручной праверкі. Няправільныя XML/JSON і непадтрыманыя кадаваньні адзначаюцца як памылкі і не прапускаюцца моўчкі. Падтрымліваюцца UTF-8, UTF-16 і кадаваньне з XML-дэклярацыі, якое разумее браўзэр. Дынамічныя інструкцыі XSLT не выконваюцца; для такіх радкоў паказваецца заўвага.

Тэчкі `Languages` і пазначаныя неанглійскія табліцы перакладаў па змаўчаньні прапускаюцца, каб ужо перакладзены тэкст не трапіў у англійскую нарыхтоўку. Інструмент не вызначае мову адвольнага тэксту: выбірайце тэчку з англійскімі зыходнікамі. Маркеры `{=!}` і `{=*}` таксама прапускаюцца.

Кожны ID экспартуецца адзін раз ва ўсім наборы. Аднолькавыя паўторы аб'ядноўваюцца. Калі тэксты адрозьніваюцца, па змаўчаньні выбіраецца першы варыянт у парадку шляхоў файлаў і ўваходжаньняў. Усе варыянты і іх крыніцы захоўваюцца ў справаздачы. Можна выбраць іншы варыянт у табліцы або прапусьціць усе канфліктныя ID праз адпаведны парамэтар.

Пры разьмеркаваньні па зыходніках шляхі падтэчак захоўваюцца, напрыклад `characters/lords.xml` → `Languages/EN/characters/std_lords_eng-GB.xml`. Калі назвы выніковых файлаў супадаюць, дадаецца нумар. Адзін ID належыць першай крыніцы выбранага варыянту. Таксама можна экспартаваць усё ў адзін XML. `language_data.xml` спасылаецца на кожны створаны файл.

Прабелы і гульнявыя канструкцыі накшталт `{FIRSTNAME}`, `{?RULER.GENDER}Lady{?}Lord{\?}` застаюцца ў тэксьце. XML-сутнасьці дэкадуюцца пры чытаньні і карэктна экранаваюцца пры экспарце; табуляцыі і пераносы радкоў у атрыбутах запісваюцца як лікавыя XML-сутнасьці. Зыходныя файлы інструмент не зьмяняе.

Гатовы прыклад `translation-EN-eng-GB.zip` сабраны з гэтай тэчкі `ModuleData`: 16 930 унікальных ID у 73 файлах радкоў, `language_data.xml` і справаздача. Для 535 ID з розным тэкстам выкарыстаны першы варыянт паводле апісанага вышэй правіла. Гэта нарыхтоўка з англійскім тэкстам.

Праверкі ў `tests` выкарыстоўваюць сапраўдны браўзэр і незалежны XML-парсэр .NET: 102 праверкі збору, інтэрфэйсу, захаваньня тэксту і экспарту; дадаткова ZIP адкрываецца праз .NET і правяраюцца ўнікальнасьць ID і ўсе спасылкі маніфэсту. Каб паўтарыць праверку, запусьціце `tests/verify-translation-preparer.ps1 -Mode Prepare`, адкрыйце створаную `.translation-tests/page.html` у асобным Edge/Chrome з `--headless --remote-debugging-port=9223` і асобнай тэчкай `--user-data-dir`, запусьціце `node tests/read-browser-results.cjs 9223` (Node 22+), потым `tests/verify-translation-preparer.ps1 -Mode Verify`. Node патрэбны толькі для тэстаў; сам HTML працуе самастойна.
